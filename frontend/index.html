§1 Identified Entities

CORE

Tiered pricing (BASIC / STANDARD / PREMIUM) per gig. Keeps gigs normalized.
CORE
orders
Tracks the full lifecycle of a purchase: PENDING → COMPLETED / CANCELLED.
TRANSACTIONAL

One wallet per user. Stores available + held (escrow) balances. Never mutated directly.

Immutable ledger. Every coin movement is recorded here. Source of truth for balance.
FINANCIAL
reviews
Post-completion review. Strictly one per order. Rating 1–5 + free-text comment.

orders 1 ──── N wallet_transactions One order produces multiple transaction events (HOLD, RELEASE/DEBIT, CREDIT)

Section 05

§5 Wallet & Escrow Flow

1

User Registration

A wallets row is created automatically. available_balance = 1000, held_balance = 0. A single CREDIT transaction is written to wallet_transactions as the opening ledger entry.

2

Client Places Order → HOLD

Inside a single DB transaction: check available_balance ≥ price, then available_balance -= price, held_balance += price, insert HOLD row in wallet_transactions, insert orders row with status = PENDING. Atomicity guarantees either all or nothing.

3

Order in Progress

Coins remain in held_balance. Neither client nor freelancer can touch them. The order status stays PENDING.

4

Client Marks Complete → RELEASE + CREDIT

Atomic transaction: orders.status = COMPLETED, completed_at = NOW(). Client wallet: held_balance -= price, insert DEBIT (escrow exit). Freelancer wallet: available_balance += price, insert CREDIT row. Two ledger entries, one DB transaction.

5

Order Cancelled → REFUND

If status = PENDING: held_balance -= price, available_balance += price on client wallet, insert REFUND row. Order status = CANCELLED, cancelled_at = NOW(). No COMPLETED order can ever be cancelled (enforced at app layer).

6

Client Leaves Review

Only permitted if orders.status = COMPLETED. App checks no row exists in reviews for this order_id, then inserts. The UNIQUE(order_id) constraint on reviews is a final guard — even a race condition can't produce two reviews for the same order.

Section 06

§6 Design Decisions

🏛️ Single Users Table

All roles share one table with a role ENUM. Avoids joining multiple identity tables for auth. Role-specific data (bio for freelancers) is nullable. Simplifies permissions checks.

📒 Ledger-Based Wallet

The wallet table holds a denormalized balance for read performance, but it is only ever mutated inside a transaction that simultaneously inserts a ledger row. You can always re-derive balance by summing wallet_transactions.

💰 Price Snapshot on Orders

price_snapshot captures the coin amount at the moment of purchase. If the freelancer later changes their package price, historical orders remain accurate — critical for financial audits.

🔒 Escrow via Held Balance

Splitting the wallet into available_balance and held_balance models a two-step escrow natively. The client can't double-spend held funds, and the freelancer can't access them until completion.

📦 Gig Packages Normalization

Extracting BASIC/STANDARD/PREMIUM into gig_packages prevents adding 9+ columns to gigs. A UNIQUE(gig_id, package_type) constraint prevents a freelancer from accidentally creating two BASIC tiers.

🔗 freelancer_id Denormalized on Orders

Although freelancer_id can be derived via gigs, storing it directly on orders allows fast dashboard queries ("all my orders") without a join, and preserves it if the gig is later deleted.

⭐ Review Integrity Guards

UNIQUE(order_id) on reviews prevents duplicates even under concurrent requests. The CHECK (reviewer_id != reviewee_id) prevents self-reviews. App layer validates order is COMPLETED before insert.

🏷️ Soft Deletes on Gigs & Users

gigs.status = 'DELETED' and users.is_active = FALSE allow logical removal without breaking FK integrity on historical orders, transactions, and reviews.

🗂️ Hierarchical Categories

Self-referential parent_id in categories supports unlimited nesting depth (e.g., "Services → Design → Logo Design") with a single table, keeping queries simple for 2–3 level hierarchies.

Section 08

§8 SQL CREATE TABLE Statements

SQL — users 
CREATE TABLE users (
  id            BIGINT UNSIGNED    NOT NULL AUTO_INCREMENT,
  username      VARCHAR(50)        NOT NULL,
  email         VARCHAR(255)       NOT NULL,
  password_hash VARCHAR(255)       NOT NULL,
  role          ENUM('CLIENT', 'FREELANCER', 'ADMIN')
                                     NOT NULL DEFAULT 'CLIENT',
  full_name     VARCHAR(100),
  avatar_url    VARCHAR(500),
  bio           TEXT,
  is_active     BOOLEAN            NOT NULL DEFAULT TRUE,
  is_verified   BOOLEAN            NOT NULL DEFAULT FALSE,
  created_at    TIMESTAMP          NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP          NOT NULL DEFAULT CURRENT_TIMESTAMP
                                     ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (id),
  UNIQUE (email),
  UNIQUE (username)
);
SQL — categories 
CREATE TABLE categories (
  id         INT UNSIGNED  NOT NULL AUTO_INCREMENT,
  name       VARCHAR(100)  NOT NULL,
  slug       VARCHAR(100)  NOT NULL,
  parent_id  INT UNSIGNED  DEFAULT NULL,
  created_at TIMESTAMP     NOT NULL DEFAULT CURRENT_TIMESTAMP,

  PRIMARY KEY (id),
  UNIQUE (slug),
  FOREIGN KEY (parent_id) REFERENCES categories(id)
    ON DELETE SET NULL
);
SQL — gigs 
CREATE TABLE gigs (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  freelancer_id BIGINT UNSIGNED NOT NULL,
  category_id   INT UNSIGNED    NOT NULL,
  title         VARCHAR(255)    NOT NULL,
  description   TEXT            NOT NULL,
  status        ENUM('ACTIVE', 'PAUSED', 'DELETED')
                                  NOT NULL DEFAULT 'ACTIVE',
  created_at    TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at    TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP
                                  ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (id),
  FOREIGN KEY (freelancer_id) REFERENCES users(id) ON DELETE CASCADE,
  FOREIGN KEY (category_id)   REFERENCES categories(id) ON DELETE RESTRICT,
  -- Composite index for browse + filter
  INDEX idx_gigs_freelancer (freelancer_id),
  INDEX idx_gigs_category_status (category_id, status)
);
SQL — gig_packages 
CREATE TABLE gig_packages (
  id             BIGINT UNSIGNED  NOT NULL AUTO_INCREMENT,
  gig_id         BIGINT UNSIGNED  NOT NULL,
  package_type   ENUM('BASIC', 'STANDARD', 'PREMIUM') NOT NULL,
  title          VARCHAR(100)     NOT NULL,
  description    TEXT,
  price          INT UNSIGNED     NOT NULL,
  delivery_days  SMALLINT UNSIGNED NOT NULL,
  revisions      TINYINT UNSIGNED NOT NULL DEFAULT 1,
  created_at     TIMESTAMP        NOT NULL DEFAULT CURRENT_TIMESTAMP,

  PRIMARY KEY (id),
  UNIQUE (gig_id, package_type),   -- one tier per gig
  CONSTRAINT chk_pkg_price    CHECK (price > 0),
  CONSTRAINT chk_pkg_delivery CHECK (delivery_days > 0),
  FOREIGN KEY (gig_id) REFERENCES gigs(id) ON DELETE CASCADE
);
SQL — orders 
CREATE TABLE orders (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  client_id       BIGINT UNSIGNED NOT NULL,
  freelancer_id   BIGINT UNSIGNED NOT NULL,
  gig_id          BIGINT UNSIGNED NOT NULL,
  package_id      BIGINT UNSIGNED DEFAULT NULL,
  price_snapshot  INT UNSIGNED    NOT NULL,   -- immutable price at order time
  requirements    TEXT,
  status          ENUM('PENDING', 'COMPLETED', 'CANCELLED')
                                  NOT NULL DEFAULT 'PENDING',
  created_at      TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  completed_at    TIMESTAMP       DEFAULT NULL,
  cancelled_at    TIMESTAMP       DEFAULT NULL,

  PRIMARY KEY (id),
  CONSTRAINT chk_order_no_selfbuy  CHECK (client_id != freelancer_id),
  CONSTRAINT chk_order_price       CHECK (price_snapshot > 0),

  FOREIGN KEY (client_id)     REFERENCES users(id)         ON DELETE RESTRICT,
  FOREIGN KEY (freelancer_id) REFERENCES users(id)         ON DELETE RESTRICT,
  FOREIGN KEY (gig_id)        REFERENCES gigs(id)          ON DELETE RESTRICT,
  FOREIGN KEY (package_id)    REFERENCES gig_packages(id)  ON DELETE SET NULL,

  INDEX idx_orders_client     (client_id),
  INDEX idx_orders_freelancer (freelancer_id),
  INDEX idx_orders_status     (status)
);
SQL — wallets 
CREATE TABLE wallets (
  id                BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  user_id           BIGINT UNSIGNED NOT NULL,
  available_balance INT UNSIGNED    NOT NULL DEFAULT 1000,
  held_balance      INT UNSIGNED    NOT NULL DEFAULT 0,
  created_at        TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  updated_at        TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP
                                    ON UPDATE CURRENT_TIMESTAMP,

  PRIMARY KEY (id),
  UNIQUE (user_id),
  CONSTRAINT chk_wallet_available CHECK (available_balance >= 0),
  CONSTRAINT chk_wallet_held      CHECK (held_balance >= 0),
  FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE
);
SQL — wallet_transactions 
CREATE TABLE wallet_transactions (
  id               BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  wallet_id        BIGINT UNSIGNED NOT NULL,
  order_id         BIGINT UNSIGNED DEFAULT NULL,
  transaction_type ENUM('CREDIT', 'DEBIT', 'HOLD', 'RELEASE', 'REFUND')
                                   NOT NULL,
  amount           INT UNSIGNED    NOT NULL,
  balance_after    INT UNSIGNED    NOT NULL,  -- snapshot: available_balance
  held_after       INT UNSIGNED    NOT NULL,  -- snapshot: held_balance
  description      VARCHAR(255),
  created_at       TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP,
  -- NOTE: No updated_at. Ledger rows are IMMUTABLE.

  PRIMARY KEY (id),
  CONSTRAINT chk_tx_amount CHECK (amount > 0),
  FOREIGN KEY (wallet_id) REFERENCES wallets(id) ON DELETE RESTRICT,
  FOREIGN KEY (order_id)  REFERENCES orders(id)  ON DELETE SET NULL,

  INDEX idx_wtx_wallet     (wallet_id),
  INDEX idx_wtx_order      (order_id),
  INDEX idx_wtx_created_at (created_at)
);
SQL — reviews 
CREATE TABLE reviews (
  id           BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  order_id     BIGINT UNSIGNED NOT NULL,
  reviewer_id  BIGINT UNSIGNED NOT NULL,
  reviewee_id  BIGINT UNSIGNED NOT NULL,
  rating       TINYINT UNSIGNED NOT NULL,
  comment      TEXT,
  created_at   TIMESTAMP       NOT NULL DEFAULT CURRENT_TIMESTAMP,

  PRIMARY KEY (id),
  UNIQUE (order_id),             -- DB-level guarantee: one review per order
  CONSTRAINT chk_rating      CHECK (rating BETWEEN 1 AND 5),
  CONSTRAINT chk_no_selfrev  CHECK (reviewer_id != reviewee_id),

  FOREIGN KEY (order_id)    REFERENCES orders(id) ON DELETE RESTRICT,
  FOREIGN KEY (reviewer_id) REFERENCES users(id)  ON DELETE RESTRICT,
  FOREIGN KEY (reviewee_id) REFERENCES users(id)  ON DELETE RESTRICT,

  INDEX idx_reviews_reviewee (reviewee_id)   -- aggregate ratings per freelancer
);
